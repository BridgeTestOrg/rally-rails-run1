System Goals & Non-Functional Requirements

Business goal
Ship Rally as a public, consumer-facing web application that anyone can sign up for and use from a browser, built and run by a solo developer or small team.
Desired end-state
A single Rails 8.1 monolith (Hotwire + importmap + SQLite, Solid Queue/Cache/Cable) deployed with Kamal to a single server. Pages are fast, user data is isolated per account and never lost, and no secrets live in the repository.
System behavior
Server-rendered HTML with Turbo and Stimulus for interactivity; responsive on mobile browsers. Users own their own records; every request is scoped to the signed-in user. No native apps, no payments, no public API, no SPA framework.
Non-functional requirements
  • architectureconfirmed
    Rails 8.1 monolith, Hotwire + importmap, no JS build step or SPA framework
    Implication: New UI is ERB + Turbo Frames/Streams + Stimulus; no React/Vue/Node bundler
  • databaseconfirmed
    SQLite in production with Solid Queue/Cache/Cable
    Implication: Avoid Postgres-only SQL; mind write concurrency; jobs via Solid Queue
  • deploymentconfirmed
    Deploy with Kamal + Dockerfile to one server
    Implication: Config via env/credentials; no multi-region assumptions
  • performanceconfirmed
    Fast pages
    Implication: No N+1 queries; index foreign keys and filtered columns; paginate lists; cache expensive fragments

  • data isolationconfirmed

    Implication: User-owned queries go through Current.user associations; authorization on every action
  • secretsconfirmed

    Implication: Encrypted Rails credentials / Kamal secrets only
